# KYB Onboarding

Anima uses Stripe Connect Custom accounts for KYB so issuing controls stay compliant while your app keeps a predictable, API-first onboarding flow.

### Connect Custom Accounts

Stripe Connect Custom accounts provide the onboarding foundation for KYB.

### Webhook-Driven Decisions

Webhook updates drive KYB state transitions and issuance readiness.

## Stripe Custom Account Configuration

Use a Stripe Custom account so requirements collection and compliance handling remain application-controlled.

```ts title="connect-account.ts"
const account = await stripe.accounts.create({
  type: "custom",
  country: "US",
  business_type: "company",
  controller: {
    fees: { payer: "application" },
    losses: { payments: "application" },
    stripe_dashboard: { type: "none" },
    requirement_collection: "application",
  },
  capabilities: {
    transfers: { requested: true },
    card_issuing: { requested: true },
  },
});
```

## KYB Status Lifecycle

KYB progresses through a predictable state machine from initiation to approval or rejection.

`not_started → pending → action_required → in_review → approved / rejected`

## API Flow

Start KYB through the API, then poll status until the onboarding state changes.

```ts title="kyb-api.ts"
const start = await fetch(
  `/api/identities/${identityId}/kyb/start`,
  { method: "POST" },
);

if (!start.ok) throw new Error("Failed to start KYB");

const status = await fetch(`/api/identities/${identityId}/kyb/status`)
  .then((res) => res.json());

console.log(status.state); // not_started | pending | action_required | in_review | approved | rejected
```

## Webhook Handling

Webhook events update the internal KYB state based on Stripe account requirements and submission status.

```ts title="stripe-webhook.ts"
if (event.type === "account.updated") {
  const account = event.data.object;

  const nextState =
    account.requirements?.disabled_reason
      ? "rejected"
      : account.requirements?.currently_due?.length
        ? "action_required"
        : account.requirements?.pending_verification?.length
          ? "in_review"
          : account.details_submitted
            ? "approved"
            : "pending";

  await updateIdentityKybState({
    stripeAccountId: account.id,
    state: nextState,
  });
}
```

## Requirements Matrix

| Business Type | Country | Required Docs |
|---|---|---|
| Individual | US | Government ID, date of birth, legal address |
| Company | US | EIN, incorporation proof, beneficial owner + controller identity |
| Company | GB / EU | Registration extract, UBO declaration, proof of trading address |

> **Warning:** Treat `action_required` as user-blocking and surface missing fields exactly as reported by Stripe requirements.

> **Warning:** Never issue cards before `approved`. If status regresses from `approved` to `action_required`, pause new issuance immediately.

> **Note:** Recommended: store both internal KYB state and raw Stripe account requirements for auditability and support triage.
