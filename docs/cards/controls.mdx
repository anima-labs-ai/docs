# Card Controls

Anima card controls let you enforce limits before authorization so agents can spend autonomously within strict policy boundaries.

## Spending Limits and MCC Rules

| Control               | Typical Value    | Behavior                                                               |
| --------------------- | ---------------- | ---------------------------------------------------------------------- |
| Per-transaction limit | $500             | Decline authorizations above single-charge threshold.                  |
| Daily limit           | $2,000 / day     | Sum same-day authorizations and block when cap is reached.             |
| Monthly limit         | $12,000 / month  | Prevent budget drift over long-running agent tasks.                    |
| MCC allow-list        | 5045, 5734, 5817 | Approve only approved software/SaaS merchant categories.               |
| MCC block-list        | 7995, 4829       | Block high-risk or prohibited categories regardless of limit headroom. |

## Velocity Controls

Frequency constraints help prevent bursty spend patterns from crossing policy boundaries even when each transaction is individually small.

> **Note:** Example: **max 5 transactions per 10 minutes** and **max 40 per day** per card.

## Pre-Approval Pattern and Stripe Issuing Deadline

Stripe Issuing gives a narrow deadline for authorization-time decisioning, so pre-approval must complete within about 2 seconds.

> **Warning:** Keep pre-approval checks synchronous and deterministic. Offload analytics or enrichment to async workers after decisioning.

## Controls API Example

```ts title="POST https://api.useanima.sh/api/identities/:id/cards/:cardId/controls"
await fetch(`https://api.useanima.sh/api/identities/${identityId}/cards/${cardId}/controls`, {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({
    spending: {
      perTransactionCents: 50000,
      dailyCents: 200000,
      monthlyCents: 1200000,
    },
    mcc: {
      mode: "allow",
      values: ["5045", "5734", "5817"],
    },
    velocity: {
      maxTransactionsPer10Min: 5,
      maxTransactionsPerDay: 40,
    },
    preApproval: {
      enabled: true,
      timeoutMs: 1500,
    },
  }),
});
```

> **Note:** Store policy snapshots with each authorization event so post-incident review can explain _which_ rule triggered a decline.

> **Tip:** Start with strict defaults and allow exceptions intentionally per card program.
