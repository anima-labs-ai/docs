# Getting Started

Give your AI agents a real email address in under 5 minutes, then validate the same flow locally before you wire up production providers.

## 1. Run Anima locally

The repository includes a startup script that boots the local stack for development:

```bash
./start.sh
```

That script starts Docker services for **Postgres**, **Redis**, **Stalwart**, and **Vaultwarden**, runs environment checks, applies Prisma migrations, and launches:

- Web app: `http://localhost:4000`
- API: `http://localhost:4001`
- OpenAPI spec: `http://localhost:4001/openapi.json`

### What works locally vs production

- **Inbound mail** can be tested locally because Stalwart runs in Docker.
- **Domain management UI** can be tested locally end-to-end.
- **Outbound SES delivery** requires valid AWS SES credentials and a verified SES identity, so that part cannot be fully exercised with the local stack alone.

If you only want to validate the custom-domain UX, DNS record generation, mailbox provisioning, and inbound pipeline, local development is enough.

## 3. Create an Agent & Send Email

<Tabs items={["Python", "Node.js"]}>
<Tab value="Python">
```python
from anima import Anima

anima = Anima(api_key="ak_...")

agent = anima.agents.create(name="Support Bot")
print(f"Agent: {agent.id}")

anima.messages.send_email(
    agent_id=agent.id,
    to="user@example.com",
    subject="Hello from Anima",
    body="This email was sent by an AI agent.",
)
print("Email sent!")
```
</Tab>
<Tab value="Node.js">
```ts
import { Anima } from "@anima-labs/sdk";

const anima = new Anima({ apiKey: "ak_..." });

const agent = await anima.agents.create({ name: "Support Bot" });
console.log(`Agent: ${agent.id}`);

await anima.messages.sendEmail({
  agentId: agent.id,
  to: "user@example.com",
  subject: "Hello from Anima",
  body: "This email was sent by an AI agent.",
});
console.log("Email sent!");
```
</Tab>
</Tabs>

## 5. Configure production outbound email

Anima uses a **hybrid email architecture**:

- **Stalwart** receives inbound mail for agent mailboxes
- **AWS SES** sends outbound mail and provides DKIM/SPF reputation
- **Anima** stores message history in its own database and search index

For custom domains, this means:

- **MX** points to your Stalwart hostname (default `mail.useanima.sh`)
- **SPF** includes `amazonses.com`
- **MAIL FROM** uses `mail.<domain>` with an SES feedback MX + SPF TXT
- **DKIM** uses SES Easy DKIM CNAME records

Before production sending works, complete these AWS SES tasks in your chosen SES region:

1. Create or use an AWS account with SES enabled.
2. Create an SES domain identity for your sending domain.
3. Configure a custom MAIL FROM subdomain such as `mail.<domain>` in SES.
4. Add the SES Easy DKIM CNAME records plus the MAIL FROM MX/TXT records in your DNS provider.
5. Publish or merge the apex SPF record with `include:amazonses.com`.
6. Create an IAM user or role that can call `ses:SendEmail` and `ses:SendRawEmail`.
7. Configure SNS bounce and complaint notifications.
8. Request SES production access so you can send to non-verified recipients.

For the DNS side of custom domains, see [Custom Domains](/docs/custom-domains). For the AWS-side setup, use the [AWS SES Setup](/docs/aws-ses-setup) runbook.
